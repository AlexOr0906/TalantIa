# Подключение формы заявки

## Текущее поведение

Пока `PUBLIC_LEAD_ENDPOINT` не задан, форма работает в безопасном демонстрационном режиме:

- проверяет телефон и обязательное согласие;
- не передаёт персональные данные;
- сообщает, что онлайн-отправка не подключена;
- предлагает позвонить по подтверждённому номеру центра.

## Будущий серверный контракт

Интерфейс готов отправлять `POST` с `Content-Type: application/json` на адрес из `PUBLIC_LEAD_ENDPOINT`:

```json
{
  "name": "Имя",
  "phone": "+79193335835",
  "interest": "Арт-студия",
  "contactMethod": "phone",
  "consent": true,
  "page": "/programs/art-studiya/",
  "company": "",
  "submissionId": "одноразовый идентификатор"
}
```

Сервер обязан повторно проверить все поля, отклонить honeypot `company`, ограничить частоту запросов и идемпотентно обрабатывать `submissionId`. Успешный ответ — HTTP 2xx. Токены, адреса получателей и другие секреты должны храниться только на сервере.

## Подключение

1. Утвердить политику обработки персональных данных и канал заявок.
2. Реализовать защищённый HTTPS endpoint с серверной валидацией, rate limit и журналированием без лишних персональных данных.
3. Установить `PUBLIC_LEAD_ENDPOINT` только в окружении сборки.
4. Проверить success/error, повторную отправку, CORS и доступность.
5. Только после этого публиковать форму как рабочий канал связи.
